# LOBO label auto-populate

This review-first integration uses the existing browser-to-Workbench lobo.handoff/v1 protocol, not a new server endpoint or PACK gateway.

1. Open Add/Edit Food. Enter the phone's trusted HTTPS Workbench origin and provide one PNG/JPEG/WebP label (1 byte to 5 MiB) using **Choose file**, drag and drop into the image area, Ctrl+V / ⌘V while the dialog is focused outside editable text fields, or **Paste image** when the browser permits clipboard access. All methods share one preview and validation.
2. Select Extract with LOBO. A previously trusted website-and-Recipe pair runs without additional authorization; otherwise authorize the built-in nutrition-label-facts Recipe in the Workbench.
3. Wellspan validates the lobo.extract.report/v1 response and renders source evidence for each returned nutrient. A serving-weight quote may omit the word serving when it is contained in a separate, matched printed serving description; the gram amount must still match exactly. Invalid or unsupported reports cannot be applied.
4. Review the original photo and the printed serving. Existing field values are unchecked by default; missing values cannot be selected.
5. Confirm that the printed serving matches your usual consumed portion, select nutrients and click Apply selected values to editor. This changes the form, not persistent state. Save Food is a separate user action under normal IndexedDB/Vega revision controls.

The requester waits up to 90 seconds for the Workbench to connect, then up to 15 minutes for a confirmed Recipe result. LOBO bounds one Recipe run at 10 minutes; preparation and review may add time. Wellspan distinguishes a connection timeout from a missing result and shows a diagnostic for a correctly authenticated result envelope that fails validation. A result arriving after expiry is refused; the client does not retry or save automatically.

Changing the selected image cancels the prior handoff listener, clears its review and revokes the old preview URL. The Paste image button may require clipboard permission; keyboard paste and Choose file remain available if permission is denied. Pasting into text fields behaves normally. No image, report or serving metadata is persisted in the Foodboard. The label image URL is revoked when closing the dialog. Rejected, malformed, expired or declined handoffs fail closed. A cancelled handoff only stops listening, not work already running on the phone. No automatic scaling or guessed values are allowed. Evidence matching is not proof of nutritional accuracy and the phone's raw OCR transcript is not available in M3. Review the original label before saving.

Acceptance: exercise picker, drop and both clipboard mechanisms; invalid type/size; multi-image and text-only paste; dialog reset and preview cleanup; supported/unsupported fixtures; perform a real phone run with the updated Android Workbench, verify selection and portion-gating, verify no write before Save Food, verify null preservation, cancel/close behavior, and offline synchronization. If Android still produces arrays, it must refuse them rather than convert quoted numbers.
